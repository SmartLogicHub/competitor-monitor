# 天猫明确下架文案变体识别设计

## 背景

天猫已下架商品页仍可能保留标题、图片、销量、历史价格与活动信息，同时在页面底部显示“商品已经下架啦～要不要瞧瞧别的～”。当前程序只匹配“商品已下架”等文案，没有覆盖“商品已经下架”，因此可能把历史残留价格当作当前价格。

## 目标

当完整页面正文出现明确的“商品/宝贝已经下架”文案时，将商品判定为明确下架，忽略页面残留价格，并让每日价格任务把价格和活动都写为 `/`。

## 设计

沿用 `ProductCollector.page_is_explicitly_unavailable()` 的精确文案列表，不引入单独匹配“下架”二字的宽泛规则。新增以下明确文案变体：

- `商品已经下架`
- `此商品已经下架`
- `宝贝已经下架`
- `此宝贝已经下架`

现有逻辑会先移除空白；“商品已经下架啦～要不要瞧瞧别的～”包含 `商品已经下架`，因此无需绑定标点、语气词或 DOM 选择器。

## 安全边界

- 页面即使仍显示 `￥2499`、补贴或销量，只要存在明确下架文案，价格必须置空并最终写 `/`。
- 不以 SKU 灰色、按钮不可点、库存文字或普通“下架”讨论判断下架，避免误判。
- 登录、风控、网络异常和页面未加载完整仍沿用现有保护逻辑，不因缺少价格而写 `/`。
- 不修改用户原始 Excel；真实复测使用已有测试副本或新副本。

## 测试

1. 新增截图场景回归测试：正文同时包含 `WH-1000XM4`、`￥2499` 和“商品已经下架啦～要不要瞧瞧别的～”，断言 `explicitly_unavailable=True` 且最终价格为空。
2. 保留现有“此商品已下架”测试，确保旧文案继续有效。
3. 运行完整 Python 与前端测试、编译检查。
4. 低速真实复测该商品页面，确认任务写 `/` 且不把 `2499` 写入。
5. 重新构建并校验另一台电脑部署包。
